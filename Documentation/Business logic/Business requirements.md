# Бизнес-требования

Дата подготовки: 2026-11-01. Статус реализации: `not-started`. Ни один endpoint или публичный API библиотеки пока не реализован.

## Согласованные требования

### Назначение и границы

`UptimeHarbor.HealthEndpoint` подключается к существующему ASP.NET Core приложению и предоставляет HTTP endpoint, совместимый с UptimeHarbor. Приложение может работать в контейнере и вне Docker. Библиотека не использует Docker API/socket, БД и отдельный агент.

Endpoint работает через существующий HTTP pipeline приложения. Библиотека не создаёт listener и не управляет портами, Kestrel, HTTPS, сертификатами, nginx или firewall. Настройки порта в библиотеке нет.

### Имя приложения

`Name` необязательно. При отсутствии явного имени используется имя приложения, предоставляемое средой хоста. Обычно это имя запускаемой сборки, совпадающее с именем проекта. `.csproj` во время работы не читается.

У явно заданного имени удаляются пробелы по краям. После этого длина должна быть 3–256 символов включительно. При превышении 256 или длине меньше 3 возникает исключение при запуске/инициализации библиотеки. Дополнительные ограничения на символы не вводятся. Явно заданная пустая строка не подменяется автоматическим именем.

Автоматическое имя берётся библиотекой без участия пользователя. Если оно длиннее 256 символов, обрезается до 256. Оно должно оставаться непустым после удаления пробелов по краям, чтобы соответствовать контракту потребителя; минимум 3 относится только к явно заданному Name. Пустое автоматическое имя вызывает понятную ошибку запуска, без генерации другого имени.

### Адрес проверки

Путь по умолчанию — `/health`, пользователь может задать другой конкретный маршрут. Настройка содержит путь, а не полный URL. Путь начинается с `/`, не содержит домен, порт, query string, fragment или шаблонные параметры маршрута.

Настройки проверяются при запуске приложения. Некорректная настройка приводит к понятной ошибке запуска. Конфликты маршрутов библиотека не обнаруживает; свободный путь и отсутствие повторного подключения обеспечивает разработчик приложения. Библиотека не удаляет и не заменяет чужие endpoints и не выбирает запасной путь. Если `/health` занят, разработчик должен переопределить Path.

### Успешный ответ

Анонимный GET должен возвращать `200 OK` и `application/json` с полями, названными именно `name` и `startedAtUtc`:

```json
{
  "name": "orders-api",
  "startedAtUtc": "2026-11-01T03:20:00Z"
}
```

`startedAtUtc` — время запуска текущего процесса приложения в UTC. Оно остаётся неизменным между запросами в пределах процесса и меняется при его перезапуске. Это не время регистрации библиотеки, запроса, загрузки ОС, создания контейнера или сборки образа.

Ответ не должен кешироваться. Endpoint допускает запрос без входа и не перенаправляет на авторизацию. В публичный ответ не включаются секреты, настройки подключений и подробности исключений.

Для JSON endpoint используются отдельные настройки библиотеки, независимые от настроек приложения. Изменение общих правил имён полей или формата времени не должно менять этот ответ.

### Ответственность приложения

Приложение обеспечивает доступность маршрута в своём pipeline и во внешней инфраструктуре. Его middleware, reverse proxy и балансировщик могут закрыть маршрут, изменить ответ, включить кеширование или перенаправление. При нескольких репликах общий URL может возвращать имя и время разных процессов; для отдельного наблюдения за процессом требуется стабильный адрес конкретного экземпляра.

### Объём проверки и поставка

Библиотека подтверждает только способность приложения отвечать на HTTP-запросы. Она не проверяет готовность БД и других зависимостей; доступный ответ не гарантирует работоспособность всех операций приложения.

Минимальная платформа — .NET 10 / ASP.NET Core 10. Версии 8 и 9 не поддерживаются. Совместимость с более новыми версиями должна подтверждаться отдельно, до её объявления.

Библиотека поставляется DLL-файлом, который копируется в `libs` целевого приложения и подключается прямой ссылкой на сборку. NuGet и ссылка на проект библиотеки не используются. Сборка и фактическая проверка такого подключения относятся к будущей реализации.

Приложение должно один раз вызвать регистрацию Add и один раз подключение Map. Специальной проверки повторных вызовов библиотека не делает. Map требует предварительного Add.

## Контракт существующего потребителя

Текущий UptimeHarbor принимает непустое имя длиной до 256 после Trim, в том числе имена длиной 1–2, и UTC с `Z` и `+00:00`. Максимальная длина библиотеки согласована с этим пределом; минимум 3 для явного Name — отдельное требование библиотеки. Подробности и источники — в [технической архитектуре](../Technical%20documentation/Architecture.md#consumer-contract).

## Критерии будущей приёмки

Подключение DLL прямой ссылкой и минимальные вызовы Add/Map дают анонимный GET по `/health`; настройка меняет имя и путь. Автоматическое имя длиннее 256 обрезается, явное вне 3–256 вызывает ошибку запуска. Невалидный Path останавливает запуск. JSON соответствует контракту потребителя независимо от общих настроек сериализации приложения. Время стабильно между запросами и относится к процессу. Ответ не кешируется библиотекой; влияние приложения и прокси документировано. Библиотека не проверяет зависимости, конфликты маршрутов и повторное подключение; ответственность приложения описана явно.

Эти критерии ещё не проверены на работающей библиотеке. Порядок реализации и проверок — в [плане](../Plans/initial-implementation-2026-11-01-(not-started)/main.md).
