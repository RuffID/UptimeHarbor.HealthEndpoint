# Конфигурация и валидация

**Состояние:** требования и проектируемое устройство; options и валидаторы не реализованы.

## Согласованные настройки

| Настройка | Значение и правило |
| --- | --- |
| `Name` | Необязательна. Если не задана, использовать `IHostEnvironment.ApplicationName`, при длине больше 256 обрезать до 256. Для явного значения выполнить Trim и проверить 3–256 символов включительно; иначе исключение при запуске. |
| `Path` | По умолчанию `/health`. Конкретный маршрут существующего приложения, начиная с `/`; без домена, порта, query string, fragment и шаблонных параметров. |
| Порт | Настройки нет; внешний порт задаётся инфраструктурой и URL мониторинга. |

Настройки проверяются при запуске приложения; некорректные значения вызывают понятную ошибку запуска. Предлагается options pattern со стартовой валидацией, например механизмом `ValidateOnStart`, без привязки endpoint к `IConfiguration`. Этот механизм ещё не реализован. Нужно гарантировать его выполнение до начала обслуживания запросов, а не только при первом обращении к options.

## Имя

Отсутствие явного значения означает применение `IHostEnvironment.ApplicationName`. Обычно это имя запускаемой сборки, совпадающее с именем проекта; хост может задать другое ApplicationName. Чтение `.csproj`, имени образа или имени контейнера во время работы не допускается.

Для явно заданной строки порядок такой: Trim, затем проверка длины. Например, `" orders-api "` даёт `orders-api`; `"ab"`, `"   "` и строка из 257 символов — ошибка запуска. Имена длиной 3, 200 и 256 допустимы. Явное имя длиннее 256 не обрезается. Символы внутри имени, включая кириллицу и пробелы, дополнительно не ограничиваются. Пустое явное значение не скрывается fallback на имя хоста.

Предлагаемая техническая мера длины — `string.Length` после Trim, согласованная с механизмом checker потребителя (UTF-16 code units). Это уточнение следует закрепить при реализации и покрыть граничными примерами; не добавлять regex допустимых символов.

Автоматическое имя нормализуется удалением пробелов по краям. Непустое значение длиной до 256 сохраняется; более длинное обрезается до 256. Порог 3 относится только к явному Name, автоматическое имя из 1–2 символов допустимо по контракту потребителя. Пустое автоматическое имя вызывает понятную ошибку запуска без генерации другого имени. Обрезка должна сохранять корректный Unicode и не разрывать surrogate pair; итоговая длина не превышает 256. Границы и строку, обрезаемую рядом с пробелами или Unicode-символом, нужно проверить при реализации.

## Путь

Проверка должна различать конкретный путь и полный URL/route template. Примеры допустимых значений: `/health`, `/monitoring/health`, `/orders/health`. Примеры ошибочных: `health`, `https://api.example.com/health`, `//api.example.com/health`, `/health?full=true`, `/health#status`, `/health/{id}`, `/health/{**rest}`. Порт относится к URL, значение `https://api.example.com:43871/health` в Path недопустимо.

Не исправлять ошибочный путь тихим добавлением `/`, удалением query или выбором другого адреса. Сообщение об ошибке должно назвать настройку и нарушенное правило без дампа конфигурации приложения.

При технической реализации проверить трактовку завершающего `/`, регистра, percent-encoding, PathBase и route groups с префиксом по правилам выбранного ASP.NET Core mapping. Валидация значения не должна пропускать полный URL или шаблон маршрута через экранирование. Проверять пересечения путей с другими endpoints не требуется. Путь не является настройкой host/port.

## Конфликты маршрутов и повторное подключение

Конфликты маршрутов библиотека не обнаруживает. Она не сканирует endpoint data sources при mapping или запуске и не обещает стартовое исключение при занятом адресе. Ответственность за свободный Path лежит на разработчике приложения.

Если `/health` уже используется, разработчик задаёт другой Path при подключении библиотеки. Библиотека подключает свой GET к указанному пути, не удаляет и не заменяет чужие endpoints и не выбирает запасной адрес. Последствия пересечений, включая неоднозначность обработки запроса, определяются маршрутизацией ASP.NET Core и конфигурацией приложения.

Add и Map должны вызываться по одному разу, Add до Map. Специальная защита от повторных вызовов не создаётся; однократное подключение обеспечивает разработчик приложения. Map без Add не должен скрыто регистрировать зависимости: отсутствие регистрации диагностируется понятной ошибкой подключения.

Корректный синтаксис Path по-прежнему проверяется при старте. Отказ от обнаружения конфликтов не отменяет эту валидацию. Собственные middleware, route groups, PathBase, reverse proxy и балансировщик относятся к ответственности приложения; библиотека не проверяет внешнюю доступность URL и не выполняет сетевых запросов.

## Фиксация и диагностика

Предложение: нормализовать и зафиксировать options до обработки запросов; runtime reload не менять молча зарегистрированный маршрут. Время процесса получить отдельно от опций и сохранить неизменным. Некорректное имя, путь или недостоверное время не маскировать текущим временем, другим именем или default Path.

Ошибки запуска диагностируются безопасно на владеющей границе, без полного options/exception dump с возможными секретами. HTTP-ответ не служит каналом подробной диагностики. Точный тип исключений определяется при технической реализации; специальной проверки повторных регистраций не будет.
