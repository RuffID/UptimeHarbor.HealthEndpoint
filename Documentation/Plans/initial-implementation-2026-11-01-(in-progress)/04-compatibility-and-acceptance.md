# 04. Проверить совместимость и принять endpoint

Статус: `completed`.

## Цель

Подтвердить совместимость endpoint с текущим потребителем UptimeHarbor и описать фактические результаты и ограничения приёмки.

## Зависимости

[Этап 03 — маршрут и JSON](03-endpoint-and-json.md). Проверяемая базовая платформа — .NET 10 / ASP.NET Core 10.

## Работы

Реализовать содержательные изолированные контрактные тесты, сверить результаты с фактическим checker UptimeHarbor без production project reference на него. Обновить документацию по реальному API и ограничениям. В изменённых C#-тестах использовать AAA-комментарии. Не менять потребителя ради прохождения контракта библиотеки.

## Затрагиваемые части

Проект библиотеки, изолированные контрактные тесты и их локальные инструкции, актуальная техническая документация и результат приёмки в плане.

## Проверки

Успешный ответ разбирается потребителем; `Z` и `+00:00` совместимы; имя после согласованной нормализации/обрезки, размер, корень и поля корректны; глобальные настройки JSON не меняют контракт. Время стабильно между запросами и соответствует старту процесса при поздней регистрации. Проверить .NET/ASP.NET Core 10 и доступность источника времени на фактически заявляемых ОС. Поддержку 8/9 не заявлять, более новые версии подтверждать отдельно. Изолированные тесты не доказывают изменение после реального перезапуска.

## Внешняя приёмка

Программа внешних проверок: реальный перезапуск процесса, существующий middleware pipeline, nginx, отсутствие redirect и cache, стабильная маршрутизация экземпляра. Запуск и сетевые действия агента требуют отдельного разрешения. Фактический объём ручной проверки и принятые ограничения зафиксированы в результате ниже; in-memory тест не подтверждает прокси или ОС.

## Критерии приёмки

Согласованные проверки пройдены на заявленной матрице, результаты и ограничения записаны; обязательная внешняя приёмка либо выполнена, либо её отдельный объём явно согласован владельцем продукта. Текущие документы скелета не являются таким согласованием.

## Результат

Изолированный объём выполнен на Windows x64 / .NET 10 / ASP.NET Core 10. Тестовый проект компилирует исходный HttpMonitoringEndpointChecker и семь необходимых чистых контрактов напрямую из соседнего uptime-harbor. Его проекты не собирались, файлы не изменялись; production-библиотека от него не зависит. Ответ настоящего health-обработчика передаётся checker через подставной HttpMessageHandler без реальной сети.

Финальный набор: 93 успешных теста, упавших 0, пропущенных 0; это 57 прежних, 18 проверок этапа 03 и 18 контрактных проверок этапа 04. Обе сборки без ошибок и предупреждений. Подтверждены точные поля и типы, явное/длинное автоматическое Unicode-имя, оба принимаемых UTC-окончания, отсутствие зоны/ненулевой offset/будущее время как отказы, регистр полей, размер 65536/65537 байт с Content-Length и без него. Максимально экранируемое имя длиной 256 даёт ответ менее 2 KiB. Позднее подключение и повторные вызовы возвращают фактический старт текущего процесса, а не время mapping/запроса. Телеметрия runner отключена.

## Ручная приёмка и ограничения

2026-11-01 пользователь подтвердил корректную работу endpoint в CostVision.Web, предоставил фактический ответ и сообщил, что после перезагрузки страницы время не меняется:

```json
{"name":"CostVision.Web","startedAtUtc":"2026-11-01T14:38:27.4243378+00:00"}
```

Ответ содержит ровно согласованные строковые поля и явное UTC-окончание +00:00. По прямому поручению пользователя этап принят и отмечен completed в этом объёме. Результаты 93 ранее выполненных изолированных тестов сохраняются; повторный запуск при обновлении статуса не проводился.

Следующие внешние сценарии не подтверждены предоставленными данными и не объявляются выполненными:

- Реальный перезапуск процесса: новое startedAtUtc после перезапуска и стабильность до него.
- HTTP-статус, Content-Type, Cache-Control, анонимность и отсутствие redirect в целевом pipeline: заголовки, URL и сведения об авторизации не предоставлены. Стабильность тела после обновления страницы сама по себе не доказывает отсутствие кеша.
- nginx, TLS и внешняя доступность с каждого назначенного наблюдателя, без redirect/кеша.
- Стабильная маршрутизация к конкретному экземпляру при нескольких репликах.
- Доступность Process.StartTime и endpoint на Linux, если Linux включается в заявляемую матрицу. Сейчас подтверждён только Windows; .NET 8/9 и более новые версии не проверялись и не заявляются.

Перезагрузка страницы не является перезапуском процесса. Перечисленные ограничения сохранены явно; основание завершения — изолированные проверки и явная пользовательская приёмка указанного ручного объёма. Зависимость этапа 05 выполнена; его реализация этим обновлением статуса не начиналась. Разрешение агенту запускать приложения или выполнять сетевые проверки не предоставлялось.
