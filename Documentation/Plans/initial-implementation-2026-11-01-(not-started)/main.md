# Первичная реализация UptimeHarbor.HealthEndpoint

Дата создания: 2026-11-01. Общий статус реализации: `not-started`.

## Основание, цель и текущее состояние

Основание — поручение подготовить независимую библиотеку для HTTP-контракта мониторинга UptimeHarbor. Согласованные требования находятся в [ТЗ](../../Business%20logic/Business%20requirements.md), фактический контракт потребителя — в [архитектуре](../../Technical%20documentation/Architecture.md#consumer-contract).

Сейчас созданы только `.slnx`, пустой `.csproj` на `net10.0`, навигация, инструкции и документация. Исходники, options, методы подключения и endpoint отсутствуют. Подготовка этого скелета не входит в этапы реализации и не переводит их в `in-progress`.

Цель будущих работ — подключаемый к существующему pipeline анонимный endpoint с точными именами JSON-полей и фактическим временем запуска процесса. Библиотека не владеет listener, портами, Kestrel, TLS, nginx, firewall, Docker и БД. Независимость от проектов UptimeHarbor обязательна; исходный репозиторий остаётся только источником контракта.

Согласованный объём: минимум .NET 10 / ASP.NET Core 10, без поддержки 8 и 9; поставка DLL прямой ссылкой из libs без NuGet и ProjectReference; автоматическое имя обрезается до 256, явное после Trim допускает 3–256 и иначе вызывает исключение при запуске. Endpoint подтверждает только способность приложения отвечать и использует отдельные настройки JSON. Конфликты маршрутов и повторное подключение библиотека не обнаруживает; разработчик обеспечивает свободный Path и один вызов Add до одного Map. Проверка синтаксиса Path при старте сохраняется.
