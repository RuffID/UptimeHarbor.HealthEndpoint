# UptimeHarbor.HealthEndpoint

Библиотека для подключения HTTP endpoint мониторинга UptimeHarbor к существующему ASP.NET Core приложению внутри контейнера или вне Docker.

**Текущее состояние на 2026-11-01:** создан только скелет решения и документация. Рабочая реализация отсутствует; публичные типы и методы ещё не существуют. Статус реализации — `not-started`.

## Состав решения

- `UptimeHarbor.HealthEndpoint.slnx` — решение с одним проектом и всеми документами как solution items.
- `UptimeHarbor.HealthEndpoint/UptimeHarbor.HealthEndpoint.csproj` — пустая SDK-style class library с начальным `net10.0` и framework reference на `Microsoft.AspNetCore.App`.
- [Документация](Documentation/README.md) — согласованные требования, подтверждённый контракт потребителя, предлагаемые API и архитектура.
- [План реализации](Documentation/Plans/initial-implementation-2026-11-01-(not-started)/main.md) и [открытые вопросы](Documentation/Plans/initial-implementation-2026-11-01-(not-started)/open-questions.md).
- [AGENTS.md](AGENTS.md) — границы работы и ответственность каталогов.

Минимальная платформа — .NET 10 / ASP.NET Core 10, цель проекта — `net10.0`. Версии 8 и 9 не поддерживаются; совместимость с более новыми версиями требует проверки. Сборка пока не выполнялась. Будущая поставка — `UptimeHarbor.HealthEndpoint.dll`, копируемая в `libs` приложения и подключаемая прямой ссылкой, без NuGet и ProjectReference.

## Будущее подключение

Пример проектируемого API, который сейчас не компилируется с этим скелетом:

```csharp
builder.Services.AddUptimeHarborHealth();

app.MapUptimeHarborHealth();
```

По требованиям анонимный GET на `/health` будет возвращать `200 OK`, `application/json`, имя приложения и неизменное в пределах процесса время его запуска в UTC. Настройки порта в библиотеке нет: используется HTTP pipeline приложения. Docker API, Docker socket, БД и отдельный агент не нужны.

Name необязательно: автоматическое имя берётся из `IHostEnvironment.ApplicationName` и при превышении лимита обрезается до 256 символов. Явное имя после Trim должно содержать 3–256 символов, иначе приложение не запускается. JSON использует отдельные настройки библиотеки. Проверки готовности зависимостей, обнаружение конфликтов маршрутов и специальная защита от повторного Add/Map не предусмотрены; свободный Path и однократное подключение обеспечивает разработчик приложения.

[Будущая инструкция подключения](Documentation/Technical%20documentation/Consumer%20integration.md) описывает также настройку имени, пути и публикацию через существующий nginx. Перечисленные там проверки ещё не выполнялись.

## Выполненная проверка скелета

Выполнена только статическая проверка структуры, XML, ссылок, solution items, согласованности документов и UTF-8. Restore, сборка, тесты, запуск приложения, сетевые проверки, упаковка и публикация не выполнялись. Подготовка документов не начинает этапы реализации.
